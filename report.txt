## 1. Unit Name
**Sprint 2.3A — Unit 8: Direct Website Discovery Plugin**

## 2. Objective
Implement the production-ready `DirectWebsiteDiscoveryPlugin` that connects the infrastructure from Units 1–7 into a working Direct Website Discovery Plugin. The plugin integrates with the existing Plugin Framework and executes the complete discovery pipeline: candidate generation → deduplication → crawling → parsing → extraction → evidence collection → confidence calculation → company assembly.

## 3. Why This Unit Exists
Units 1–7 built the complete infrastructure layer (URL normalization, deduplication, confidence, evidence, extractor interfaces, candidate generator interface, config view). Unit 8 is the **capstone implementation** that wires this infrastructure into a production plugin conforming to `BaseDiscoveryPlugin`. Without Unit 8, the infrastructure is inert — no plugin exists to execute the pipeline.

## 4. Architecture Placement
```
SourceOrchestrator (priority 40)
    ↓
PluginSource (capability=COMPANY_DISCOVERY)
    ↓
PluginManager.discover_all()
    ↓
DirectWebsiteDiscoveryPlugin (BaseDiscoveryPlugin)
    ↓
    ├── PluginConfigView → typed config access
    ├── CandidateGenerator (e.g., BraveSearchGenerator) → list[Candidate]
    ├── DuplicateURLFilter → deduplicated candidates
    ├── HTTPCrawler → CrawlResponse
    ├── HTMLParser → ParsedPage (PageContent protocol)
    ├── FieldExtractor implementations (7) → list[ExtractionResult]
    ├── EvidenceSet + FieldEvidence → provenance tracking
    ├── Confidence calculation → per-field confidence
    └── Company Assembly → list[dict] for SourceOrchestrator
```
