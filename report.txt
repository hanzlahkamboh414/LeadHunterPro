1. WHAT WE WANT TO MAKE  (Vision & Permanent Goal)
--------------------------------------------------------------------------------
LeadHunter Pro is a REAL, production-grade company-discovery platform, not a
search-API client. Target domain: construction/contractor leads, Texas-first.

Tagline goal (CLAUDE.md rule #10 — the "Execute" button must eventually perform
real discovery):

    Search Internet
        ↓  Find Companies
        ↓  Visit Websites
        ↓  Extract Company Information
        ↓  Extract Decision Makers
        ↓  Validate
        ↓  Rank
        ↓  Return Results

It must NEVER become:

    Read Fixture JSON  →  Return Cached Companies

Fixtures exist ONLY as an emergency bridge (ADR-002). They are temporary bridge
data, surfaced honestly as `data_source="fixture"`, `bridge_mode=true`, with a
`fallback_reason` — never disguised as live leads.

Planned stack: Python 3.12 + FastAPI backend, PostgreSQL (lazy SQLAlchemy),
React/Electron client, Ollama (local LLM), FAISS (vector/semantic discovery).
Search APIs (Brave, SearXNG, Google CSE, Bing) are OPTIONAL, replaceable
sources — never the core architecture.

--------------------------------------------------------------------------------
2. ARCHITECTURE  (How it is built)
--------------------------------------------------------------------------------
Correct flow (rule #4 — every source replaceable):

    Discovery Engine
        ↓
    Source Orchestrator          (SourceOrchestrator)
        ↓
    Multiple Sources            (DirectoryCrawlSource · SearchProviderSource · FixtureSource)
        ↓
    Crawler / Extractor         (HttpCrawler, session manager)
        ↓
    Validation + Ranking        (Phase 2 pipeline)
        ↓
    Results

Incorrect pattern (forbidden):  Connector → Brave API → Results.

Layer direction (PROJECT_PRINCIPLES): api → services → engines → connectors →
crawlers → utilities. Dependencies flow down only; every connector and every AI
provider is replaceable behind a stable interface.

Public surfaces:
  - GET /api/v1/connectors/texas-procurement   (connector surface)
  - GET /api/v1/discovery/companies            (discovery surface)
