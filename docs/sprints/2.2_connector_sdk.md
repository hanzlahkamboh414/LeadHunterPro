## Objective

Solidify the **Source Connector SDK** as the standard mechanism for discovering construction companies from external data sources. Replace the ad-hoc public-search approach (Sprint 2.1) with a pluggable connector architecture that supports multiple independent data sources.

---

## Background

Sprint 2.1 introduced the Company Discovery Engine which searches Google and Bing SERPs. While functional, this approach has limitations:

- Search-engine results are unreliable (CAPTCHAs, rate limits).
- Results are noisy and require heavy downstream cleaning.
- No structured, domain-specific data (industry focus, revenue tier).

The Connector SDK addresses these by providing a clean abstraction over known, curated, or portal-scraped data sources.

## Architecture

```
app/engines/source_connectors/
├── base.py              # ConstructionSourceConnector ABC
├── sdk.py               # CompanyResult, ConnectorRegistry, ConnectorConfig
├── sdk_utils.py         # ConnectorLogger, HTTPClient, retry decorator
├── texas_procurement.py # Texas construction procurement data
└── example_connector.py # Template for new connectors
```

### Key Contracts

**`ConstructionSourceConnector`** (base.py):
```python
class ConstructionSourceConnector(ABC):
    @property
    def name(self) -> str: ...

    @property
    def description(self) -> str: ...

    def is_available(self) -> bool: ...

    @abstractmethod
    def discover(self, *, state, city, industry, limit) -> tuple[list[dict], dict]:
        ...
```

**`CompanyResult`** (sdk.py) — frozen dataclass returned by connectors.

**`ConnectorRegistry`** (sdk.py) — singleton for managing active connectors.
