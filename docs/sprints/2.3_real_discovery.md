## 1. Problem Statement

### Current State (Sprint 2.2)

The discovery system returns **fixture data only**. The `_fetch_live()` method in `TexasProcurementConnector` is a placeholder returning `[]`. The `CompanyDiscoveryEngine` works correctly but has nothing real to process.

```
GET /api/v1/discovery/companies?industry=Roofing&location=Dallas+Texas
→ Returns 5 companies from texas_procurement.json
→ total_in_dataset = 89 (all fixture)
→ No live web source is queried
→ "Execute" button performs instant lookup, not real discovery
```

### Root Cause

Per [source_validation_report.md](source_validation_report.md):
- TxDOT → `robots.txt` returns 403 (blocked)
- AGC Texas → `robots.txt` returns 403 (blocked)
- BuildZoom → blocks all crawlers
- ThomasNet → paywalled partner API
- County bid portals → moderate feasibility, TBD per portal

**No free, publicly-scrapable high-volume source exists.** But several low-volume, legally-permissible public pages do exist and can be crawled with appropriate rate limiting.

### What Must Change

1. Fix the **crawlers/robots.py** async bug (`run_until_complete` on running loop)
2. Create a **web-source connector** that uses the existing crawler infrastructure
3. Make the pipeline prefer live results; use fixtures only as fallback
4. Extract rich company data (name, URL, city, trade, email, phone) from discovered pages
5. Update all documentation and tests

## 4. Fix: Crawler robots.py Async Bug

**File:** `app/crawlers/robots.py`, lines 134–142

**Bug:** When called from an async context (inside an already-running event loop), the code tries to call `loop.run_until_complete(future)` which raises `RuntimeError: This event loop is already running`.

**Fix:** Use `asyncio.ensure_future()` / `asyncio.create_task()` instead, returning the coroutine directly.

```python
# BEFORE (broken):
import asyncio
try:
    loop = asyncio.get_running_loop()
except RuntimeError:
    return asyncio.run(_check())
else:
    future = loop.create_task(_check())
    return loop.run_until_complete(future)  # CRASHES inside async context

# AFTER (fixed):
import asyncio
try:
    loop = asyncio.get_running_loop()
except RuntimeError:
    return asyncio.run(_check())
else:
    return await _check()  # Just await directly when in async context
```

**Impact:** All crawler integration tests must be re-run after this fix. The bug prevents the crawler from working in any async context (including FastAPI route handlers).
